# Flight Dispatch

A Windows desktop flight planning companion for SimBrief and VATSIM. Built with Electron, React, and TypeScript. All settings and flight history stay on your computer.

> **v1.0.0 rebuilt October 20, 2026.** The current downloads include automatic simulator detection, a centered landing-rate popup, live actual-versus-planned timings and an off-block countdown, along with the enhanced route explorer and earlier updates. If these controls are missing from your briefing, download again; the version number remains 1.0.0.

## Install and set up

The current release is **v1.0.0**, containing the complete current app and VATSIM companion. Complete both service setups before your first automatic dispatch.

### Requirements

- A 64-bit Windows PC and an internet connection for sign-in, generation, filing and live airport data. Release builds target Windows x64.
- A SimBrief/Navigraph account and its SimBrief Pilot ID or username; a VATSIM account for automatic filing.
- Microsoft Edge or Google Chrome installed for SimBrief. **Automatic** browser selection tries Edge first, then Chrome.
- A normal Brave, Edge or Chrome profile for the VATSIM companion. Use the profile where VATSIM already signs in successfully. The companion requires Chromium 120 or later and permission to load unpacked extensions. Firefox is not supported by this companion.

The released installer and portable app include the application runtime. **Node.js, npm and a separate Playwright browser download are not needed to run them.** Gate-provider API keys are optional; SimBrief generation and VATSIM filing do not require developer API keys.

### 1. Install or open Flight Dispatch

Choose one build from `release/`:

| Build | Setup |
| --- | --- |
| [Flight-Dispatch-Setup-1.0.0.exe](https://github.com/sudoshipit/flight-dispatch/releases/download/v1.0.0/Flight-Dispatch-Setup-1.0.0.exe) | Run the installer, choose an installation directory, then open the desktop shortcut. |
| [Flight-Dispatch-1.0.0-Portable.exe](https://github.com/sudoshipit/flight-dispatch/releases/download/v1.0.0/Flight-Dispatch-1.0.0-Portable.exe) | Save the executable in a folder you want to keep and run it directly. No installation is required. |

Close older copies of Flight Dispatch first. Check the version at the bottom of the app's sidebar: it should say **v1.0.0**. The current rebuild includes a slim flight banner, live timings near the top, an orange/red off-block countdown, a SimBrief flight picker and automatic **Flight recorder** detection. Both builds store settings/history in your Windows profile rather than beside the executable. These builds are unsigned; this project does not include a code-signing certificate. Checksums are in the release's **SHA256SUMS.txt**, and **BUILD-INFO.json** identifies the exact source commit and build time.

### 2. Connect SimBrief

1. Open **Settings** and enter your own **SimBrief Pilot ID or username**. A new installation starts with this field blank; no personal account is bundled.
2. Choose **SimBrief sign-in browser**. This setting controls SimBrief only.
3. Select **Save preferences** before signing in so the app uses your chosen ID and browser.
4. Select **Sign in to SimBrief**. Complete sign-in and any verification in the browser, using the account matching your saved Pilot ID or username.
5. **Close all windows belonging to that dedicated Flight Dispatch browser profile.** This releases the profile for background generation. Do not close Flight Dispatch itself. Your everyday browser can remain open.

The dedicated profile has its own session; being signed in to SimBrief in your everyday browser does not sign this profile in automatically. If the session expires during generation, the app opens a sign-in window and resumes after you sign in and close that profile's windows.

### 3. Connect VATSIM with the companion extension

VATSIM uses your everyday browser session. Unlike SimBrief, **keep the VATSIM browser open after signing in**. Do not install this companion into SimBrief's dedicated profile.

1. Keep Flight Dispatch open and go to **Settings → VATSIM browser connection**.
2. Select **Set up VATSIM companion**. The app creates/updates the extension folder, opens it in File Explorer, and copies its path. The usual location is `%APPDATA%\flight-dispatch\vatsim-companion`; use the actual path displayed in Settings.
3. In the browser profile where VATSIM works, open the appropriate Extensions page:

   | Browser | Address |
   | --- | --- |
   | Brave | `brave://extensions` |
   | Microsoft Edge | `edge://extensions` |
   | Google Chrome | `chrome://extensions` |

4. Enable **Developer mode**, then choose **Load unpacked**. Paste the copied path into the folder picker's address bar, press Enter, and select that folder. Select the folder containing `manifest.json`, not the file itself.
5. Load the folder generated by the app, **not the repository's `companion/` folder**. The generated folder includes the local connection configuration and filing adapter required to run the extension.
6. Confirm that **Flight Dispatch — VATSIM Companion** is enabled. Return to the app and wait for **Connected** under **VATSIM browser connection**. This confirms the browser-to-app connection; it does not itself confirm VATSIM account sign-in.
7. Select **Sign in to VATSIM** in Settings. With the companion connected, this opens VATSIM in that same browser. Complete sign-in if required; an existing valid session can be reused.
8. **Leave that browser running.** It may be minimized. You can close the sign-in tab, but do not exit the browser. Ordinary filing opens an inactive tab, submits automatically, confirms the result, and closes the tab. Login or verification brings the tab forward until you finish.

Install the companion in **one browser profile only**. Keep Developer mode enabled and retain the generated folder; unpacked extensions run from that folder. Setup is not needed for every flight. The companion popup in the browser's Extensions menu shows connection status and offers **Reconnect**. Organization-managed browsers may prohibit unpacked extensions; use a browser/profile where installation is permitted.

The generated folder contains a local pairing secret and should not be shared. The repository's extension source contains no per-install pairing secret.

### 4. Save filing preferences and aircraft defaults

1. In **Settings**, leave **Automatically file on VATSIM** enabled for Generate → File → Briefing. Turning it off generates a plan without filing; the briefing still offers **File automatically on VATSIM** when you decide to file.
2. Review **Cost index rules**: SWA/all aircraft **40**, DAL/A319/A320/A321 **25**, DAL/B738/B739 **35**. Add/edit rules as needed. `*` matches all aircraft for an airline; aircraft-specific rules take precedence. Unmatched aircraft use SimBrief defaults.
3. Select **Save preferences** after changing settings.
4. On **New flight**, select **Aircraft type**, then **Variant or airframe**. **Set as default for [aircraft]** saves that variant immediately. For personal SimBrief airframes, select the base aircraft, choose **Sync my airframes**, then select a synced variant and save it as the default if wanted.
5. Check the full passenger capacity for the selected variant. **Full flight** uses that capacity; **Auto** lets SimBrief randomize the load; **Custom** accepts an explicit count, including zero.

New flight clears flight details and sets departure date and off-block time to **current UTC + 30 minutes**, including the next UTC date when crossing midnight. Both fields remain editable. Saved variant defaults apply after you select the aircraft type. Personal airframes are associated with your saved SimBrief ID; sync them again for another account.

### 5. Set up gate information, if wanted

Gate lookup is optional. No gate key is needed for planning, filing, weather, CTAFs or the route map.

1. In **Settings → Gate information**, choose **Aviationstack · Free personal plan**, **FlightAware AeroAPI · Optional paid provider**, or **Off · Saved suggestions only**.
2. For a provider, choose **Get an API key**, obtain a key from your provider account, and paste it into **Gate provider API key** in the app. A normal FlightAware website login is not an AeroAPI key. Do not put keys in chat or the repository.
3. Set **Monthly request limit in this app** to suit your allowance. The default is 90; the cap excludes requests from other apps sharing that key.
4. Select **Save preferences**. Saved keys display **Key saved · enter a new key to replace**. To remove a key, choose **Remove saved key**, then save preferences.
5. In a briefing, use **Check gates**. Missing gates remain unavailable; gates previously retrieved for matching flights can appear with a historical label. No paid historical endpoints are called.

Keys are encrypted using Windows through Electron safeStorage. Provider coverage, quotas and limitations are described under [Integration boundaries](#integration-boundaries). A valid key does not guarantee gate data for every flight.

### 6. Generate your first flight

1. Open **New flight**. Enter the airline prefix in **Callsign** (for example, `SWA`) and the number in **Flight number** (`123`). The combined callsign is `SWA123`.
2. Select aircraft/variant and enter departure/destination ICAOs. Departure date and off-block time default to **current UTC + 30 minutes**; adjust either field if needed. The fields and their pickers use the selected UTC values.
3. Select the passenger mode. Optionally paste a **Custom route** and set taxi times, extra fuel, final reserve, cruise altitude and alternate. Blank optional planning fields use SimBrief defaults.
4. Confirm SimBrief's dedicated sign-in windows are closed and the VATSIM companion browser is running. Choose **Generate & file flight plan**.
5. Follow the progress screen. If prompted, finish SimBrief sign-in and close its windows, or finish VATSIM sign-in/verification and **keep its browser open**. Work resumes automatically; no click on VATSIM's File button is needed.
6. Check the briefing's filing result. **Filed on VATSIM** appears only after a new success confirmation. Failures produce a persistent alert and a Windows notification.

**Import latest from SimBrief** still imports your most recently generated OFP in one click. **Choose from SimBrief**, beside it on New flight and Recent flights, opens a searchable list of generated plans saved in your SimBrief account. Select by callsign, route, aircraft, UTC departure and release; **Upcoming only** filters later departures. Click **Import selected flight** to load that exact OFP. Refresh list retrieves up to 500 recent releases from SimBrief Dispatch History. If needed, sign in through the dedicated SimBrief browser, then close its windows to resume. No extra API key is needed. Saved flight options without a generated OFP must first be generated in SimBrief. Neither import action generates or files another flight. Use **File automatically on VATSIM** from that briefing to submit it. Refreshing the briefing/weather/gates updates airport data; **Edit & regenerate** recalculates the plan after planning changes.

### Replacing an earlier build or updating later

1. Finish or cancel any dispatch, then close the old Flight Dispatch app. Run the new installer, or open the new portable executable. Check the sidebar version so an old shortcut does not leave you using the previous build.
2. Settings and flight history remain in your Windows profile. For a backup, close the app and copy `%APPDATA%\flight-dispatch\data` to a private location. API keys may need re-entry on another Windows account/computer.
3. If your earlier build did not use the VATSIM companion, complete its setup once. Old dedicated-profile VATSIM sessions are not transferred to your everyday browser; sign in there if needed. The SimBrief dedicated profile is retained.
4. If the companion is already installed, open the updated app first to refresh its folder, then choose **Reload** on the extension card. This is required when moving from the previous development builds to this v1.0.0 package too. Wait for **Connected** in Settings and keep using the same generated folder.
5. Retry only flights marked as failed before submission. For an **unconfirmed** submission, use **Review on VATSIM** first; the app intentionally does not automatically retry it.

## Features

- SimBrief's official supported-aircraft catalog, refreshed daily or on demand, with a bundled offline copy. Passenger capacities come from SimBrief's airframe endpoint. Includes the official variants (477 in this snapshot). Personal airframes sync from the signed-in SimBrief options page, including passenger limits; no private API is used. Saved personal variants are scoped to the configured SimBrief ID.
- Editable cost index rules: SWA all aircraft **40**; DAL A319/A320/A321 **25**; DAL B738/B739 **35**. Aircraft-specific rules override airline wildcard rules. Unmatched aircraft retain SimBrief defaults. Types without CI support use their own cruise profiles.
- Passenger loading: SimBrief **AUTO**, the selected variant's full capacity, or an explicit number including zero. SimBrief performs its own load randomization.
- Optional taxi-out/taxi-in minutes, extra fuel minutes, final reserve, cruise altitude and alternate. Blank inputs use SimBrief defaults; zero is preserved. **Edit & regenerate** restores the request and generates a new OFP so fuel and timing changes are recalculated. The existing filed snapshot is preserved.
- Automatically determined route, cruise altitude, time enroute, and fuel endurance from the generated OFP.
- Optional custom route input accepts pasted waypoints, airways, coordinates, and speed/level changes. The app normalizes whitespace and case, passes the route to SimBrief, and verifies it is loaded before automatic generation. SimBrief's resulting route is used for VATSIM filing.
- New flight opens with empty flight fields on launch and every time you choose **New flight**. Passenger loading resets to Auto; saved variant preferences apply after you select an aircraft. **Edit & regenerate** still restores the selected plan deliberately.
- The route explorer appears only on the briefing, at top right. Click a waypoint or use its picker to inspect planned altitude, UTC time/date, wind, temperature, groundspeed and remaining fuel. Climb/cruise/descent legs have distinct colors; TOC/TOD use diamond markers. Expand the map for a larger view, drag to pan, Ctrl + scroll or double-click to zoom, and use Fit route to reset. Keyboard: Tab to a waypoint and Enter/Space to select; focus the map and use arrows to pan, +/− to zoom, Home to fit, and Escape to close the expanded view. Geographic detail is bundled and works offline; missing OFP coordinates leave gaps.
- Detailed OFP briefing: estimated and scheduled out/off/on/in UTC times with dates; taxi, airborne, block and endurance durations; block/takeoff/landing fuel plus trip, contingency, alternate, final reserve, extra and ETOPS fuel; cost index, cruise/climb/descent profiles, Mach, average winds and head/tailwind, ISA deviation, tropopause and step climbs. Fuel and weights retain the OFP's LBS/KGS units.
- SID and STAR names, transitions, and planned runways. Missing procedures and transitions display **None**. Procedures sit immediately below airport weather, frequencies and gates, ahead of the statistics, timings and fuel.
- Expandable weights/payload and waypoint log with planned altitude, ETO, wind, temperature, groundspeed, and fuel remaining. Waypoint ETO is calculated from estimated takeoff plus cumulative navlog time, including UTC date changes. Missing numbers remain unavailable; zero stays zero.
- VATSIM: **IFR**, generated callsign/type/wake/route/times/altitude/speed/alternate, **equipment L**, **blank transponder**, **Voice**, and blank optional section-18 details to match the supplied screenshot. The user's written blank-transponder instruction overrides the screenshot's LB1 value.
- Clickable combined callsign links to the specific SimBrief briefing.
- Departure and arrival METARs from NOAA Aviation Weather Center, manual refresh, observation times, and explicit stale/snapshot labels. Weather requests are batched and cached for one minute.
- Destination elevation and designated CTAF frequencies from VATSIM AIP. SimBrief elevation is a fallback. Multiple designated CTAFs are preserved; missing CTAFs are not guessed.
- Optional gates from Aviationstack or FlightAware AeroAPI. Matches callsign, route, and date. An absent gate can fall back to a previously observed gate for the same flight and route, clearly labeled with source/date. Saved observations expire after 30 days.
- A 15-minute gate-request cache, request deduplication, and a configurable local monthly cap (90 by default). No paid historical endpoints are called. The cap covers this app only; other apps using the same key count against the provider's quota separately.
- Automatic simulator detection and landing recording, with ft/min, UTC timestamp, groundspeed, pitch/bank, repeated contacts and distance from the planned destination. Touchdown opens a centered popup on any app page, and the result stays at the top of the briefing and in Recent flights.
- Live actual-versus-planned flight timeline: off-block, takeoff, touchdown and on-block UTC times; taxi-out, air time, taxi-in and total block durations. Running windows update every second, with remaining/over-plan time and saved final differences.
- Local history for the latest 30 generated/imported briefings, persistent preferences, and encrypted API keys using Electron safeStorage / Windows encryption.

## Landing recorder setup

1. Generate or import the flight you are about to fly, or open its saved briefing. **Flight recorder** automatically searches for a supported simulator; no tracking button is required. Start/load the simulator flight and leave pause/replay before departure.
2. Keep Flight Dispatch running; switching pages does not stop tracking. Only one briefing is tracked at a time. Browsing other saved flights does not steal an active recording. Generating/importing a new flight replaces a pending briefing only if it has never connected to a simulator.
3. After at least three seconds of observed airborne telemetry and reaching 30 ft AGL, the recorder arms. Touchdown opens a centered **Your landing rate** popup, even while viewing Settings or another page, and creates **Your landing** at the top of the briefing. Dismiss the popup with its button or Escape; **View briefing** returns to the flight. Later measurement refinements and parking completion update the result without reopening a dismissed popup. New ground contacts can show a new popup.
4. After landing, remain below 3 kt with the parking brake set for five seconds to complete automatically. If an add-on does not report its parking brake, select **Finish tracking**. Results and timing transitions are saved as observed. After restarting the app, open the unfinished briefing to reconnect; a briefing that already contains a landing result is never automatically recorded again.
5. **Stop tracking** stops automatic detection for that briefing for the rest of this app session. **Resume tracking** lets you explicitly restart, select a simulator, or change the X-Plane UDP port under **Connection setup**. Open **Recent flights** to review saved rates and timings. Importing the same OFP and filing it on VATSIM preserve both. Use a new OFP for the next flight.

### Live actual-versus-planned timings

The **Live flight timeline** compares observed UTC timestamps with SimBrief's estimated times, falling back to scheduled times when estimates are absent. It also shows planned and actual taxi-out, air time, taxi-in and total block durations. Active windows count up every second; their difference shows time remaining or time over plan. Completed windows show signed differences (`+` means later or longer).

Before departure, **Until off blocks** counts down to the planned UTC departure every second, including across midnight. The countdown is green above 10 minutes, orange **Off blocks soon** in the final 10 minutes, and red **Off blocks overdue** after planned departure, counting upward. The slim flight banner spans the briefing width, with live timings directly below beside the map (stacked in smaller windows). It stops when off-block movement is observed, and is not shown as a departure countdown when tracking begins midair.

- **Off blocks** is the first movement at or above 1 kt, with the parking brake released, sustained for two seconds after observing the aircraft stationary. The recorded time is the beginning of that movement, including pushback.
- **Takeoff** is the first observed ground-to-air transition, confirmed after three seconds airborne and reaching 30 ft AGL.
- **Touchdown** uses the recorder's detected contact. Brief bounces do not restart taxi-in timing. Sustained flight after a touch-and-go returns to air time; the final landing supplies the arrival timestamp.
- **On block** is the start of a five-second period below 3 kt with the parking brake set after landing. Selecting **Finish tracking** manually does not invent an on-block time.
- Durations use the real UTC clock, including simulator pauses and elapsed time while disconnected; they are not accelerated simulator time. The recorder does not infer transitions during a data gap, replay, slew or loading. Joining midair or after taxi has started leaves any unobserved departure timestamps blank. Stopping tracking freezes unfinished durations at the last observation; reopening the briefing preserves recorded milestones.

| Simulator | Connection and measurement |
| --- | --- |
| MSFS 2020 / 2024 on Windows | SimConnect, using the simulator's touchdown normal velocity when a fresh value is available, converted from ft/sec to ft/min. Falls back to the last airborne sample with an **Estimated** label. No SDK or separate helper installation is needed for the usual local connection. |
| FSX SP2 / Steam Edition and Prepar3D | SimConnect-compatible connection; estimated rate from the last airborne vertical-speed sample. Uses the older SimConnect protocol and standard variables. |
| X-Plane 11 / 12 | Built-in RREF UDP telemetry at 20 Hz on this PC, normally port **49000**. No plugin or API key is required. **Connection setup** in the recorder lets you change the port to match X-Plane. Rate is estimated from the last airborne vertical-velocity sample. |
| Other simulators / Xbox / cloud streaming | No connector is included. A simulator must expose a supported telemetry interface; SimBrief and VATSIM alone cannot provide touchdown measurements. |

**Auto detect** locks to the first simulator that supplies valid, live, unpaused telemetry and stays with that simulator through reconnects. If both simulator families are running, stop tracking and select one explicitly before resuming. X-Plane traffic is restricted to `127.0.0.1`; it is not a network-PC setup. SimConnect discovery honors an existing `SimConnect.cfg`, then searches the local simulator connection. An invalid/stale configuration is reported as a connection error. For an existing remote SimConnect setup, keep its configured address/port accessible; this app does not edit simulator configuration files.

If connection stays pending, load into the aircraft (not just the simulator's main menu), confirm the selected simulator/UDP port, and check Windows Firewall rules for the app and simulator. For X-Plane, verify its receiving UDP port in network settings. For SimConnect, check any existing `SimConnect.cfg` and restart the simulator. No simulator controls are written by the recorder.

Rates are negative for descent. X-Plane/older-simulator measurements are sampled estimates, not exact impact measurements; sample age is shown. Pauses, X-Plane replay, slew/loading states, backward simulator time, large position jumps and telemetry gaps reset detection rather than infer a landing across missing data. Keep replay and third-party replay tools off while recording; their behavior varies, particularly on SimConnect simulators. A brief low bounce is counted separately; this is not an aircraft structural-load or landing-quality assessment. G-force is not calculated. UTC timestamps use the PC clock, not the simulator's selected date.

The connectors and detection logic have automated fixture/transport tests, including localhost X-Plane UDP. Live landings in each simulator and add-on aircraft still need validation; compatibility above describes the implemented interfaces, not a claim that every simulator/aircraft combination has been flight-tested.

## Setup and filing troubleshooting

| Symptom | What to check |
| --- | --- |
| SimBrief browser cannot start, or generation waits for it to close | Install/select Edge or Chrome, save preferences, and close every window in the dedicated Flight Dispatch profile. Your everyday browser may stay open. |
| SimBrief is signed in elsewhere but this app asks again | Its dedicated profile has a separate session. Use **Sign in to SimBrief**, sign in to the account matching your saved Pilot ID, then close that profile's windows. |
| **Setup needed** or **VATSIM companion is not connected** | Open both the app and the browser/profile containing the companion. Confirm the extension is enabled and VATSIM site access is allowed. Use **Reconnect** in its popup; after an app update, **Reload** the extension. This is a connection status, not an account sign-in status. |
| Extension cannot load or reports a missing configuration/module | Use **Set up VATSIM companion** again and load that generated folder. Do not load the repository source folder, a ZIP file, or the manifest file itself. |
| Companion says **Another browser is connected** | Keep it enabled only in the intended profile. Disable the other copy, then use **Reconnect** in the intended profile. |
| Local VATSIM connection could not start | Close other copies of Flight Dispatch and restart. The companion uses `127.0.0.1:49773`; another process occupying that port prevents connection. No router port forwarding is needed. |
| VATSIM asks for sign-in after setup | **Connected** confirms the companion connection, not account authentication. Use **Sign in to VATSIM** with the companion connected, and keep that browser open. |
| VATSIM requires browser verification | Complete verification in the existing tab; filing resumes there. Verification is labelled separately from login. The app does not solve challenges. For persistent loops in your everyday browser, see [Cloudflare troubleshooting](https://developers.cloudflare.com/cloudflare-challenges/troubleshooting/challenge-solve-issues/). |
| Filing failed before submission | Read the alert, correct the connection/login/form issue, then select **Retry automatic filing**. The generated SimBrief plan remains available. |
| Submission could not be confirmed | Use **Review on VATSIM** first. The plan may already be filed, so the app does not automatically retry. Cancelling cannot retract a submitted plan. |
| Gate information is missing | Check the provider, saved key and request limit. Try **Check gates** after the cache interval. Some flights have no gate data even with a valid key. |
| A saved aircraft variant is missing | Check the base aircraft and SimBrief ID, use **Sync my airframes**, then select an available variant and save its default again if needed. |

VATSIM filing stays in your everyday browser session. A ready filing form takes precedence over an unrelated Sign In link or embedded verification widget. If an unfamiliar form stops filing, preserve the alert message for troubleshooting instead of repeatedly submitting the flight.

## Integration boundaries

**Generation and filing need the user's authenticated sessions.** The app uses SimBrief's documented dispatch redirect plus the public OFP fetcher, and VATSIM's prefile page. It does not use an unapproved private filing API, bypass sign-in, or require a SimBrief developer API key.

The page adapters check rendered controls, set requested values, and click the normal generation/filing button automatically. They stop when required controls are missing or flight identity differs. SimBrief uses a separate persistent Edge/Chrome profile with normal browser sign-in and background generation. VATSIM uses a Manifest V3 companion extension in the user's normal browser. The extension opens an inactive VATSIM tab, fills and submits the form, then closes that tab after confirmation. Only sign-in or verification brings it forward. This avoids moving VATSIM into an automated headless browser after login. Cloudflare documents limitations for automated browsers; challenges still require the user. [Cloudflare supported browsers](https://developers.cloudflare.com/cloudflare-challenges/reference/supported-browsers/)

The companion connects to a local WebSocket server bound to `127.0.0.1:49773`, authenticated with a per-install secret and an extension-origin check. It accepts only specific commands for VATSIM tabs it opened. No public debugging port, arbitrary script endpoint, cookie permission or password collection is used. A lost connection never replays a pending filing command. The app and browser must both remain open. The extension has VATSIM site access, scripting, storage and alarms permissions; the setup folder includes the local pairing secret and should not be shared. [Chrome extension scripting](https://developer.chrome.com/docs/extensions/reference/api/scripting) · [Edge unpacked-extension setup](https://learn.microsoft.com/en-us/microsoft-edge/extensions/getting-started/extension-sideloading)

The app only displays **Filed on VATSIM** after detecting a new success message after submission. It saves the submission intent before clicking. A submitted-but-unconfirmed plan is never automatically resubmitted; **Review on VATSIM** opens the same browser profile for inspection. A failed attempt before submission offers **Retry automatic filing**. Cancelling automation cannot retract an already submitted flight plan. Newly generated plans are correlated with the requested flight identity, aircraft, departure time, CI, explicit passenger count, generation timestamp, request ID, and static ID when returned; route and variant are checked on the options form.

Browsers retain sessions in their own storage. VATSIM credentials stay in the chosen everyday browser; SimBrief uses its dedicated profile. Complete sign-in, MFA and provider verification in the browser when prompted. The app does not read passwords or browser profile files. Existing local settings/history are retained when installing a replacement build. A fresh installation contains no Pilot ID, API keys, browser sessions, pairing secret or flight history; the pairing secret is generated locally on first launch.

**Gate availability varies.** Aviationstack's free personal plan lists 100 requests/month and current flight data; historical access requires a paid plan. Gate fields can be missing. This app's history consists of gates previously retrieved locally, not an unlimited free historical database. FlightAware is an optional paid alternative. [Aviationstack pricing](https://aviationstack.com/pricing) · [Gate fields and coverage](https://aviationstack.com/faq)

**Map navigation data comes from the generated OFP.** The route uses SimBrief navlog coordinates and the AIRAC cycle reported for that plan. It is not a direct connection to Navigraph's licensed navigation database, a procedure chart, or a pre-generation airway resolver. Direct Navigraph access requires [approved application credentials](https://developers.navigraph.com/docs/request-access) and an eligible user subscription. No application credentials were supplied. The background is bundled public-domain [Natural Earth](https://www.naturalearthdata.com/about/terms-of-use/) land geometry distributed by `world-atlas`; it works offline. Missing waypoint coordinates leave gaps rather than inventing route legs.

**OFP details are a planning snapshot.** Refreshing METARs, gates or AIP information does not recalculate fuel, winds, procedures or times. Use **Edit & regenerate** to change planning options, or reimport the latest OFP after regenerating it in SimBrief. Older saved briefings remain usable; reimport a flight while it is the latest OFP to add any missing fields.

Only flight simulation use is intended.

## Development

This section is for running/building from source. Install Node.js 24 and npm, plus Edge or Chrome for SimBrief. The packaged application does not require the Node.js/npm toolchain. Open PowerShell in your downloaded or cloned repository directory:

```powershell
npm ci
npm run dev
```

Complete the same account and companion setup described above. Normal source runs use the same Windows application data directory as packaged runs, so close the packaged app first. To run a production renderer build locally, use `npm run build` followed by `npm start`. To create the Windows x64 installer and portable executable in `release/`, use `npm run package`; close any running `release/win-unpacked/Flight Dispatch.exe` first.

```powershell
npm test             # Domain, form-adapter, caching, quota and persistence tests
npm run check:live   # Read-only aircraft / OFP / METAR / VATSIM AIP checks
npm run build        # TypeScript check and renderer build
npx playwright install chromium # Browser for isolated extension tests
npm run test:smoke
node scripts/import-smoke.mjs   # Electron UI smoke test; uses a temporary user profile
npm run test:dispatch # Complete automatic generation + filing with local service mocks
npm run test:browser  # Dedicated browser session and personal-airframe fixture checks
npm run package      # Windows x64 portable executable and NSIS installer
```

If bundled Chromium cannot launch on Windows, use installed Edge for companion tests in a temporary profile:

```powershell
$env:FLIGHT_DISPATCH_TEST_BROWSER = 'msedge'
npm run test:smoke
npm run test:dispatch
Remove-Item Env:FLIGHT_DISPATCH_TEST_BROWSER
```

To test the packaged app after building:

```powershell
$env:FLIGHT_DISPATCH_TEST_BROWSER = 'msedge'
$env:FLIGHT_DISPATCH_EXECUTABLE = (Resolve-Path -LiteralPath 'release\win-unpacked\Flight Dispatch.exe').Path
npm run test:dispatch
Remove-Item Env:FLIGHT_DISPATCH_EXECUTABLE
Remove-Item Env:FLIGHT_DISPATCH_TEST_BROWSER
```

`npm run check:live` checks public aircraft and airport data using a sample route by default. To opt into reading your own latest OFP, set `$env:SIMBRIEF_TEST_USER` to your Pilot ID or username for that command, then remove the environment variable. Never commit your own OFP, screenshots, account ID or keys as test fixtures.

Landing tests replay airborne/ground telemetry, native and estimated measurements, bounces, pauses, disconnects, persistence and UDP subscriptions without attaching to a live simulator. The desktop smoke test verifies automatic tracking, the centered landing popup, live timers, the off-block countdown and overdue state, saved timing transitions, history preservation, map inspector/zoom/expanded view and procedure order. Tests use temporary application/browser profiles. Companion tests load the real extension, resolve VATSIM hosts to a local HTTPS fixture server and block other DNS in that browser. SimBrief generation uses local fixture pages. The UI smoke test also makes read-only public airport/catalog calls. Tests do not generate/file real flights or attach to everyday browser sessions. Local test certificates under `tests/https/` are excluded from release builds.

The complete Generate → File → Briefing checks cover requested fields, route/planning overrides, variant capacity, existing signed-in sessions, login recovery, separate verification prompts, cancellation, one submission, failure alerts and confirmation. Live authenticated generation/filing still needs verification with each user's account after setup. Gate normalization, caching, matching and quotas have automated tests; live API-key gate lookups have not been tested without a user-supplied key.

Development structure:

| Directory | Purpose |
| --- | --- |
| `src/` | Desktop UI, briefing, history, settings |
| `shared/domain.mjs` | CI rules, validation, OFP parsing, URL construction, gate selection |
| `electron/main.mjs` | Desktop window, restricted IPC, dispatch orchestration |
| `electron/browser.mjs` | SimBrief normal sign-in, dedicated profile and background generation |
| `electron/vatsim-bridge.mjs` | Authenticated local companion connection and non-replaying requests |
| `companion/` | VATSIM browser extension, visible-page state checks and connection popup |
| `electron/automation.mjs` | Visible-page adapters for signed-in SimBrief/VATSIM |
| `electron/services.mjs` | Public data adapters, caching, request limits |
| `electron/store.mjs` | Atomic local storage and encrypted secrets |
| `data/aircraft.json` | Official SimBrief catalog snapshot for offline launch |
| `tests/` | Domain, service and form-adapter regression tests |

Local application data is stored beneath Electron's Windows `userData` directory, normally `%APPDATA%/flight-dispatch/data`. SimBrief sessions and extensions use the adjacent `browser-profile/msedge` or `browser-profile/chrome` directory. The installed VATSIM extension is in `vatsim-companion`; its pairing secret is also saved in `vatsim-companion-connection.json` beside that directory. Remote pages have no Electron preload or Node bridge. Cancelling dispatch cannot retract an already submitted flight and leaves a sign-in/verification tab available for the user.
